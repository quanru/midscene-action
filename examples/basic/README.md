# Midscene Test example

A standalone `@midscene/test` project using YAML cases, Playwright, and a real
vision model. The TypeScript configuration opens a local greeting form in Chromium
and cleans up the Agent and browser after the run.

The case asks the AI to enter Alice and submit the form, then uses `aiAssert` to
check the visible greeting. A custom `expectGreeting` Node also checks the DOM.
The test command is simply `midscene-test`; model configuration errors are
handled by Midscene when the AI steps run. Reports and Markdown summaries are
generated by Midscene Test itself.

## Run locally

Use Node >= 22.13 and npm:

```bash
cd examples/basic
npm ci
npx playwright install chromium
cp .env.example .env
```

Fill in `.env` with your model API key, name, and family according to the
[Midscene model configuration](https://www.midscenejs.com/model-config).
Set `MIDSCENE_MODEL_BASE_URL` if your provider requires a custom endpoint.
The configuration loads `.env` beside `midscene.config.ts` automatically.
Existing shell variables take precedence, including variables provided by CI.
Run the tests:

```bash
npm test
```

Run `npm run typecheck` to check the TypeScript configuration.
Set `HEADLESS=false` to watch the browser. `npm run nodes` generates the Node Spec.
The native report is under `midscene_run/report/`, with structured results and
`result.md` under `.midscene/test-results/<run-id>/`.

Use a clean output directory for each run: the Action expects one native run.

## CI

The `example-basic.yml` workflow installs this project and Chromium, then runs `npm test` through
`uses: ./` with `publish-pages: false`. The example calls the real model and
must pass. CI downloads its report artifact and verifies that the native HTML report exists. Only manual publication runs curl against the published HTML report.

Configure the repository's `CI` environment with:

- Secret: `MIDSCENE_MODEL_API_KEY`.
- Variables or secrets: `MIDSCENE_MODEL_NAME`, `MIDSCENE_MODEL_FAMILY`.
- Optional variable or secret: `MIDSCENE_MODEL_BASE_URL`.

Fork PRs run quality checks only because GitHub does not provide model secrets.
Missing configuration in other CI runs fails the job. Manually dispatch `example-basic.yml` with
`publish-pages` enabled to publish the same example to Cloudflare Workers and check the
deployed report URLs with curl.

For publication, also configure the `CI` environment with:

- Secret: `CLOUDFLARE_API_TOKEN` with Workers Admin permission at the Workers product scope for automatic creation, or Editor scoped to an existing Worker (verify Preview token support in CI).
- Variable: `CLOUDFLARE_ACCOUNT_ID`. The default Worker name is `midscene-reports`; the first publication creates it.
  Initialize the account’s workers.dev subdomain in the dashboard before first use.

Each run or rerun creates a Preview named `run-<run_id>-<run_attempt>` and gets an
independent report URL. On the free plan, Cloudflare keeps up to 100 Previews per
Worker and deletes the least recently deployed Preview when full.
