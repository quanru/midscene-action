# Midscene Action

English | [简体中文](README.zh-CN.md)

Run Midscene tests in GitHub Actions and save reports, with optional publishing to GitHub Pages.

Use this Action to:

- Run Midscene tests.
- View results in the Summary and download test reports.
- Publish reports to GitHub Pages to browse current and past reports online.

Set up dependencies, install browsers, start your application, and configure the model in your workflow before running this Action. The Action runs your test command and collects the reports generated by your Midscene project.

## Usage

See [action.yml](action.yml) for all available inputs.

The Action uploads the HTML reports and result files generated by your tests as a GitHub Actions artifact. Download the ZIP file from the **Artifacts** section of the workflow run page.

```yaml
- uses: web-infra-dev/midscene-action@v1
  with:
    # Required: Bash command to run your tests. Install dependencies first.
    command: npm test

    # Required: directory of your Midscene test project. There is no default.
    # tests/midscene is only an example; use '.' for a project at the repository root.
    working-directory: tests/midscene

    # Name of the uploaded reports in the Artifacts section of the run page.
    # Use a different name for each upload in the same run.
    # Default: midscene-results
    artifact-name: midscene-results

    # Number of days to keep the uploaded reports in GitHub Actions.
    # The artifact is automatically deleted after this period.
    # Default: 14
    retention-days: '14'

    # Publish to GitHub Pages; accepts only 'true' or 'false'.
    # Default: false
    publish-pages: 'false'
```

You can customize `artifact-name`. Letters, numbers, hyphens, and underscores are recommended, for example `midscene-results` or `midscene-chromium`. Each upload within the same workflow run must use a different name; separate runs can reuse the same name.

### Basic usage

The following example assumes your test project is in `tests/midscene` and uses npm and Playwright Chromium. Adjust the installation steps and test command for your project.

```yaml
name: Midscene tests

on:
  push:
  workflow_dispatch:

permissions:
  contents: read

jobs:
  test:
    runs-on: ubuntu-24.04
    timeout-minutes: 20
    env:
      MIDSCENE_MODEL_API_KEY: ${{ secrets.MIDSCENE_MODEL_API_KEY }}
      MIDSCENE_MODEL_NAME: ${{ vars.MIDSCENE_MODEL_NAME }}
      MIDSCENE_MODEL_FAMILY: ${{ vars.MIDSCENE_MODEL_FAMILY }}
      MIDSCENE_MODEL_BASE_URL: ${{ vars.MIDSCENE_MODEL_BASE_URL }}
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-node@v6
        with:
          node-version: '24'
      - name: Install dependencies and browser
        working-directory: tests/midscene
        run: |
          npm ci
          npx playwright install --with-deps chromium
      - name: Run Midscene tests
        id: midscene
        uses: web-infra-dev/midscene-action@v1
        with:
          working-directory: tests/midscene
          command: npm test
```

By default, the Action runs tests, uploads reports, and shows results in the Summary. To use another test command, such as `command: pnpm test`, install the package manager and dependencies in earlier steps.

## Publishing to GitHub Pages

First, go to Settings → Pages → Build and deployment and set **Source** to **GitHub Actions**. See the [GitHub Pages documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) for setup instructions.

Add publishing permissions and an environment to the job in the basic example, then enable `publish-pages`. The following is a job configuration snippet; keep the checkout, Node setup, and installation steps from the basic example:

```yaml
permissions:
  contents: read
  actions: read
  pages: write
  id-token: write

environment:
  name: CI
  url: ${{ steps.midscene.outputs.page-url }}

steps:
  # Keep the checkout, Node setup, and installation steps here.
  - name: Run tests and publish reports
    id: midscene
    uses: web-infra-dev/midscene-action@v1
    with:
      working-directory: tests/midscene
      command: npm test
      publish-pages: 'true'
```

Replace `CI` with your environment and configure its credentials and allowed deployment branches. Tests and publishing share the job's environment and permissions. See [actions/deploy-pages](https://github.com/actions/deploy-pages#security-considerations) for deployment requirements.

Add `concurrency` at the workflow level so deployments to the same site run one at a time:

```yaml
concurrency:
  group: midscene-pages
  cancel-in-progress: false
```

**Pages configuration is checked before tests run.** If the check fails, the Action prints setup instructions, skips tests, report uploads, and the Summary, and returns a failure. Any installation steps before the Action will already have run.

After publishing succeeds, the Summary links to the report for this run. The site's home page lists previous runs whose reports are still available.

## Reports and results

View test results in the workflow **Summary** and download reports from **Artifacts**. When Pages is enabled and publishing succeeds, the Summary includes a link to the online report.

If tests fail, the Action still collects reports and tries to publish them when Pages is enabled. The Action then fails.

## Outputs

Read outputs with `${{ steps.midscene.outputs.<name> }}`:

| Output                 | Description                                  |
| ---------------------- | -------------------------------------------- |
| `test-result`          | Status of the test command.                  |
| `report-artifact-name` | Name of the artifact containing the reports. |
| `artifact-url`         | Link to the artifact download page.          |
| `page-url`             | Pages site URL after successful publishing.  |
| `publication-result`   | Status of the deployment step.               |
