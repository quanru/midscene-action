# Midscene Action

English | [简体中文](README.zh-CN.md)

Run Midscene tests in GitHub Actions and save reports, with optional publishing to Cloudflare Workers.

Use this Action to:

- Run Midscene tests.
- View results in the Summary and download test reports.
- Publish each run’s report to Cloudflare Workers with its own URL.

Set up dependencies, install browsers, start your application, and configure the model in your workflow before running this Action. The Action runs your test command and collects the reports generated by your Midscene project.

## Usage

See [action.yml](action.yml) for all available inputs.

The Action uploads the HTML reports and result files generated by your tests as a GitHub Actions artifact. Download the ZIP file from the **Artifacts** section of the workflow run page.

```yaml
- uses: web-infra-dev/midscene-action@v1
  with:
    # Required: Bash command to run your tests. Install dependencies first.
    command: npm test

    # Required: directory of your Midscene test project. There is no default.
    # tests/midscene is only an example; use '.' for a project at the repository root.
    working-directory: tests/midscene

    # Name of the uploaded reports in the Artifacts section of the run page.
    # Use a different name for each upload in the same run.
    # Default: midscene-results
    artifact-name: midscene-results

    # Number of days to keep the uploaded reports in GitHub Actions.
    # The artifact is automatically deleted after this period.
    # Default: 14
    retention-days: '14'

    # Publish to Cloudflare Workers; accepts only 'true' or 'false'.
    # Default: false
    publish-pages: 'false'
```

You can customize `artifact-name`. Letters, numbers, hyphens, and underscores are recommended, for example `midscene-results` or `midscene-chromium`. Each upload within the same workflow run must use a different name; separate runs can reuse the same name.

### Basic usage

The following example assumes your test project is in `tests/midscene` and uses npm and Playwright Chromium. Adjust the installation steps and test command for your project.

```yaml
name: Midscene tests

on:
  push:
  workflow_dispatch:

permissions:
  contents: read

jobs:
  test:
    runs-on: ubuntu-24.04
    timeout-minutes: 20
    env:
      MIDSCENE_MODEL_API_KEY: ${{ secrets.MIDSCENE_MODEL_API_KEY }}
      MIDSCENE_MODEL_NAME: ${{ vars.MIDSCENE_MODEL_NAME }}
      MIDSCENE_MODEL_FAMILY: ${{ vars.MIDSCENE_MODEL_FAMILY }}
      MIDSCENE_MODEL_BASE_URL: ${{ vars.MIDSCENE_MODEL_BASE_URL }}
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-node@v6
        with:
          node-version: '24'
      - name: Install dependencies and browser
        working-directory: tests/midscene
        run: |
          npm ci
          npx playwright install --with-deps chromium
      - name: Run Midscene tests
        id: midscene
        uses: web-infra-dev/midscene-action@v1
        with:
          working-directory: tests/midscene
          command: npm test
```

By default, the Action runs tests, uploads reports, and shows results in the Summary. To use another test command, such as `command: pnpm test`, install the package manager and dependencies in earlier steps.

## Publishing to Cloudflare Workers

Enable publishing to get an online report link in the workflow Summary. Set up your Cloudflare credentials and GitHub repository settings first.

### 1. Create a Cloudflare API Token

1. Sign in to the [Cloudflare dashboard](https://dash.cloudflare.com/) and open **My Profile → API Tokens**.
2. Select **Create Token → Custom Token → Get started** and name it, for example, `midscene-reports`.
3. Grant **Admin** at the **Workers product** scope for the account that will host your reports. This lets the Action create the Worker on first publication. Restrict the token to that account.
4. Select **Continue to summary → Create Token** and copy the token. Its value is shown only once.

See Cloudflare’s [token creation guide](https://developers.cloudflare.com/fundamentals/api/get-started/create-token/) and [Workers permissions](https://developers.cloudflare.com/workers/authorization/workers/).

### 2. Get your Cloudflare Account ID

Select the same account in the Cloudflare dashboard and copy its **Account ID**. See [Find your Account ID](https://developers.cloudflare.com/fundamentals/account/find-account-and-zone-ids/).

If you have not used Workers before, open **Workers & Pages** and set up your account’s `workers.dev` subdomain.

### 3. Configure GitHub repository credentials

In your GitHub repository, open **Settings → Secrets and variables → Actions**:

- On the **Secrets** tab, select **New repository secret**. Set the name to `CLOUDFLARE_API_TOKEN` and paste the token as its value.
- On the **Variables** tab, select **New repository variable**. Set the name to `CLOUDFLARE_ACCOUNT_ID` and paste your Account ID as its value.

### 4. Enable report publishing

Pass the configured credentials to the Action:

```yaml
- name: Run tests and publish reports
  id: midscene
  uses: web-infra-dev/midscene-action@v1
  with:
    working-directory: tests/midscene
    command: npm test
    publish-pages: 'true'
    cloudflare-api-token: ${{ secrets.CLOUDFLARE_API_TOKEN }}
    cloudflare-account-id: ${{ vars.CLOUDFLARE_ACCOUNT_ID }}
```

The Worker name defaults to `midscene-reports`; set `cloudflare-worker-name` to use another name. The Action creates the Worker on first publication. Each run or rerun gets its own report URL in the Summary.

Required publishing inputs are checked before tests start. Wrangler validates credentials and permissions during deployment; deployment failure fails the Action even if tests passed.

Use a clean test output directory: publishing expects exactly one `.midscene/test-results/*/summary.json` with an existing HTML report.

## Reports and results

View test results in the workflow **Summary** and download reports from **Artifacts**. When publishing is enabled and publishing succeeds, the Summary includes a link to the online report.

If tests fail, the Action still collects reports and tries to publish them when publishing is enabled. The Action then fails.

## Outputs

Read outputs with `${{ steps.midscene.outputs.<name> }}`:

| Output                 | Description                                  |
| ---------------------- | -------------------------------------------- |
| `test-result`          | Status of the test command.                  |
| `report-artifact-name` | Name of the artifact containing the reports. |
| `artifact-url`         | Link to the artifact download page.          |
| `page-url`             | This run’s report URL after publishing.      |
| `publication-result`   | Status of the deployment step.               |
