# Contributing

## Setup

Use Node 24 (`nvm use`), or Node >= 22.13:

```bash
pnpm install --frozen-lockfile
pnpm check
```

The project uses ECMAScript modules, Rslint for
JavaScript, and Prettier for formatting all supported files including YAML. `pnpm install --frozen-lockfile` enables the Husky pre-commit hook in a Git checkout; it checks lint
and formatting without modifying or staging files.

## Layout

```text
action.yml                     Composite Action entry point
src/cloudflare-report.mjs      Native report preparation and Wrangler config
examples/basic/                Complete Midscene Test browser project
.github/workflows/ci.yml        Lint and formatting checks
.github/workflows/example-basic.yml  Example E2E and manual Cloudflare publication
```

`pnpm lint` checks JavaScript and TypeScript with Rslint and formatting with Prettier.
`pnpm format` applies Rslint fixes, then formats the entire project with Prettier.
Use `pnpm check` before submitting changes; CI runs the same checks
on Node 22 and 24. The separate example workflow exercises the composite Action
on a GitHub runner; the workflows run independently.

VS Code is configured to run Rslint fixes and Prettier on save. Install the
recommended Rstack and Prettier extensions; the editor uses the same project
configurations as the CLI.

`rslint.config.mjs` uses the built-in JavaScript and TypeScript recommended presets
and Node globals. Prettier handles formatting. YAML is checked by Prettier for syntax and formatting;
Rslint does not run custom YAML parser rules.

## Action changes

Keep `action.yml` inputs and outputs, README tables, and caller examples in sync.
Preserve failures after collecting reports. Run the example and verify its reports
when changing report handling. Report paths are resolved relative to the native summary file in the caller’s test directory.

The `example-basic.yml` workflow installs `examples/basic` and runs real AI cases through `uses: ./`.
The example must pass. CI downloads its report artifact and verifies the native HTML report exists. Ordinary CI does not start a local HTTP server. There is no separate unit or shell test suite.
`pnpm check` runs lint and formatting; run `npm test` in `examples/basic` for local E2E.
Configure model credentials in the `CI` environment (see the example README).
Fork PRs run quality checks only because model secrets are unavailable.

Artifact upload and deployment require a GitHub runner. Manually dispatch
`example-basic.yml` with `publish-pages` enabled to check a Cloudflare deployment with curl.
Configure `CLOUDFLARE_API_TOKEN` as a secret and `CLOUDFLARE_ACCOUNT_ID` as a variable in the `CI` environment. The token needs
Workers Admin permission at the Workers product scope for automatic creation, or Editor scoped to an existing Worker (verify Preview token support in CI). Initialize the account’s workers.dev subdomain in the dashboard before first use. No Pages project is needed.

The Action copies the native HTML report directory to a temporary directory and
publishes it as a Cloudflare Workers Preview deployment. The temporary Wrangler configuration is generated by the Action; no server-side Worker script is needed. Previews are named by run ID and attempt. The free plan keeps up to 100 Previews per Worker, deleting the least recently deployed when full. The Action does not merge historical reports. Native Markdown results and downloadable report artifacts
remain independent of deployment.

## Release

This is a composite Action: there is no npm publication or bundle build. Consumers
load `action.yml` and `src/` directly from the chosen Git ref.

After merging a reviewed change with passing CI, a maintainer can publish a
version tag such as `v1.0.0` and update the corresponding major ref (`v1`) to that
release. Update examples for breaking changes. Consumers do not need to install this repository’s development dependencies.
